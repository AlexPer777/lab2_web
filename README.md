# Лабораторная работа №2 — Веб-программирование

Веб-приложение для проверки попадания точки в заданную область на координатной плоскости. Продолжение [лабораторной работы №1](https://github.com/AlexPer777/lab1_web): вычисления и проверка данных переносятся на FastCGI-сервер на Java.

**Вариант:** 824152.

## Задание

Доработать ЛР №1: разработать FastCGI-сервер на Java и HTML-страницу, которая отправляет координаты точки и радиус на сервер посредством HTTP GET-запроса.

Сервер должен проверять корректность параметров, определять попадание точки в область и возвращать результат в виде HTML-страницы с таблицей либо JSON. Предыдущие результаты должны сохраняться между запросами и отображаться в таблице. Ответ также должен содержать текущее время и время выполнения обработки.

## Возможности по заданию

- Ввод координат X, Y и выбор радиуса R.
- Проверка данных на сервере.
- Определение попадания точки в заданную область.
- Асинхронная отправка GET-запросов из JavaScript без перезагрузки страницы — AJAX (Asynchronous JavaScript and XML).
- Таблица результатов с координатами, радиусом, результатом, текущим временем и временем обработки.
- Сохранение и отображение предыдущих проверок между запросами.

## Входные данные

| Параметр | Допустимые значения | Способ ввода |
| --- | --- | --- |
| X | −3, −2, −1, 0, 1, 2, 3, 4, 5 | Радиокнопки |
| Y | `−3 < Y < 3` | Текстовое поле |
| R | 1, 1.5, 2, 2.5, 3 | Выпадающий список |

Ограничения указаны для варианта 824152. Проверка параметров должна выполняться и при обращении к серверу напрямую, в обход формы.

## Область попадания

Область состоит из трёх фигур. Границы фигур входят в область.

| Часть области | Условия попадания |
| --- | --- |
| Прямоугольник во II четверти | `−R/2 ≤ x ≤ 0`, `0 ≤ y ≤ R` |
| Четверть круга в III четверти | `x ≤ 0`, `y ≤ 0`, `x² + y² ≤ R²/4` |
| Треугольник в IV четверти | `x ≥ 0`, `y ≤ 0`, `y ≥ 2x − R` |

Точка попадает в область, если выполняются условия хотя бы одной из фигур. Вершины треугольника: `(0, 0)`, `(R/2, 0)`, `(0, −R)`.

## Технологии

| Технология | Назначение по заданию |
| --- | --- |
| HTML, CSS | Страница, форма и таблица результатов |
| JavaScript, AJAX | Отправка запросов и обновление страницы без полной перезагрузки |
| HTTP GET | Передача X, Y и R в параметрах запроса |
| Java, FastCGI | Проверка данных и вычисление результата |
| Apache httpd | Обслуживание статических файлов и передача динамических запросов FastCGI-серверу |

FastCGI — протокол взаимодействия веб-сервера с приложением. Apache принимает HTTP-запросы браузера, а Java-приложение получает динамические запросы через FastCGI.

## Развёртывание по заданию

1. Поднять Apache httpd на Helios от имени своего пользователя.
2. Настроить выдачу статических файлов HTML, CSS и JavaScript через Apache.
3. Поднять Java FastCGI-сервер на Helios с библиотекой `fastcgi-lib.jar` из материалов лабораторной работы.
4. Настроить передачу динамических запросов из Apache в FastCGI-приложение.
5. Организовать GET-запросы из JavaScript и обновление таблицы результатами ответа.

Шаблон `httpd-conf-template.conf` и библиотека `fastcgi-lib.jar` предоставляются в LMS.

## Состояние репозитория

Реализована клиентская часть для варианта 824152:

- `index.html` — страница с оформлением, графиком области, формой ввода и таблицей результатов.
- `index.js` — отрисовка графика и точек, проверка введённых данных, отправка GET-запросов через `fetch` и сохранение полученных результатов в `localStorage`.
- X выбирается радиокнопками от −3 до 5, Y вводится в текстовое поле строго между −3 и 3, R выбирается из списка `1; 1,5; 2; 2,5; 3`.
- При смене R на графике отображаются только точки, проверенные с выбранным радиусом.

Форма отправляет X, Y, R на `/fcgi-bin/server.jar` без перезагрузки страницы. Таблица и график обновляются по ответу Java-сервера. В таблице отображаются время сервера и время обработки запроса; во время запроса кнопки проверки и очистки заблокированы. Для старых записей без времени обработки выводится прочерк.

В `server/src/Main.java` добавлен Java FastCGI-сервер с библиотекой `server/lib/fastcgi-lib.jar` из материалов лабораторной. Класс `PointRequest` разбирает GET-параметры `x`, `y`, `r` и проверяет допустимые значения. Для Y и R поддерживаются точка и запятая; десятичные числа обрабатываются через `BigDecimal`.

Класс `AreaChecker` проверяет попадание в прямоугольник, четверть круга и треугольник. Границы фигур входят в область. Расчёты выполняются через `BigDecimal`.

На запрос с параметрами `x=1&y=-0.5&r=2.5` сервер возвращает координаты, результат и время. Пример ответа:

```json
{"x":1,"y":-0.5,"r":2.5,"hit":true,"timestamp":"2026-11-01T12:00:00Z","executionTimeMs":0.25}
```

`timestamp` — текущее время сервера в UTC в формате ISO 8601. `executionTimeMs` — длительность проверки параметров и расчёта в миллисекундах, измеренная через `System.nanoTime()`. Ожидание запроса и передача ответа в неё не входят.

Отсутствующие, повторяющиеся, неизвестные и неверные параметры приводят к ответу `400 Bad Request` с JSON-описанием ошибки. Для остальных HTTP-методов возвращается `405 Method Not Allowed`.

Для проверки через браузер страницу нужно открывать через Apache: он должен обслуживать статические файлы и передавать запросы `/fcgi-bin/server.jar` Java FastCGI-серверу. Открытие `index.html` как файла или через обычный статический сервер не обеспечивает работу запросов. В `apache/httpd.conf` добавлена конфигурация для Helios: каталог `/home/studs/s501851/httpd-root`, HTTP-порт `24666`, FastCGI-порт `24777`. Запуск Apache и Java на Helios подтверждён пользователем. Полная проверка формы и истории через браузер остаётся заключительным шагом.

## Сборка и запуск сервера

Для локальной сборки используется JDK 27 с целевой версией Java 21 для Helios. Команды выполняются из корня репозитория:

```sh
mkdir -p server/build/classes
javac --release 21 -encoding UTF-8 -cp server/lib/fastcgi-lib.jar -d server/build/classes server/src/*.java
jar --create --file server/build/server.jar --manifest server/manifest.mf -C server/build/classes .
cp server/lib/fastcgi-lib.jar server/build/fastcgi-lib.jar
java -DFCGI_PORT=24777 -jar server/build/server.jar
```

Рядом с `server.jar` должна находиться библиотека `fastcgi-lib.jar`: путь к ней указан в манифесте JAR. Остановка Java-сервера — `Ctrl+C`.

Сервер собирается с `--release 21` и запускается на Java 21 или новее. Локальный JDK 27 поддерживает такую сборку.

На Helios проверь конфигурацию:

```sh
chmod 700 ~/httpd-root/run
httpd -t -f ~/httpd-root/conf/httpd.conf
```

Продолжай после сообщения `Syntax OK`. В одном терминале на Helios запусти Java:

```sh
java -DFCGI_PORT=24777 -jar ~/httpd-root/fcgi-bin/server.jar
```

В другом терминале на Helios запусти Apache от своего пользователя:

```sh
httpd -f ~/httpd-root/conf/httpd.conf -k start
```

Для проверки через SSH-туннель выполни на Mac:

```sh
ssh -p 2222 -L 8080:127.0.0.1:24666 s501851@helios.cs.ifmo.ru
```

Оставь SSH-соединение открытым и перейди в браузере на `http://localhost:8080/`. Для проверки сервера напрямую через тот же туннель:

```sh
curl -i 'http://localhost:8080/fcgi-bin/server.jar?x=1&y=-0.5&r=2.5'
curl -i 'http://localhost:8080/fcgi-bin/server.jar?x=1&y=3&r=2.5'
```

Первый запрос должен вернуть `200 OK` и `hit: true`, второй — `400 Bad Request`. Также проверь форму и сохранение истории после перезагрузки страницы.

Остановка Apache на Helios:

```sh

```

Логи находятся в `~/httpd-root/error.log` и `~/httpd-root/access.log`. Конфигурация использует пути модулей из выданного шаблона Helios и не предназначена для штатного Apache в macOS.


## Проверка работы

После сборки Java-классов запусти проверки параметров и границ области:

```sh
mkdir -p server/build/test-classes
javac --release 21 -encoding UTF-8 -cp server/build/classes -d server/build/test-classes server/test/ServerTest.java
java -cp server/build/classes:server/build/test-classes ServerTest
```

Ожидаемый вывод: `Passed: 53`. Тесты выполняются без Apache и не входят в серверный JAR.

При работающем сервере и SSH-туннеле проверь форму:

| X | Y | R | Ожидаемый результат |
| --- | --- | --- | --- |
| −1 | 2 | 2 | Попадание, граница прямоугольника |
| −1 | −0,75 | 2,5 | Попадание, граница круга |
| −1 | −0,76 | 2,5 | Промах |
| 1 | −0,5 | 2,5 | Попадание, граница треугольника |
| 1 | −0,6 | 2,5 | Промах |
| 0 | 3 или −3 | 3 | Ошибка ввода |

В инструментах разработчика браузера на вкладке Network должен появляться GET-запрос к `/fcgi-bin/server.jar` с параметрами `x`, `y`, `r`. Страница при отправке формы не перезагружается. В ответе должны быть `hit`, `timestamp` и `executionTimeMs`.

Проверка сервера в обход формы:

```sh
curl -i 'http://localhost:8080/fcgi-bin/server.jar?x=1&y=-0.5&r=2.5'
curl -i 'http://localhost:8080/fcgi-bin/server.jar?x=1&y=3&r=2.5'
curl -i 'http://localhost:8080/fcgi-bin/server.jar?x=6&y=0&r=2'
curl -i 'http://localhost:8080/fcgi-bin/server.jar?x=0&y=0&r=4'
curl -i 'http://localhost:8080/fcgi-bin/server.jar?x=0&y=0&r=1&r=2'
curl -i -X POST 'http://localhost:8080/fcgi-bin/server.jar'
```

Первый запрос должен вернуть `200`, следующие четыре — `400`, последний — `405`.

После нескольких проверок перезагрузи страницу: история должна сохраниться. При смене R на графике должны оставаться только точки с выбранным радиусом. Кнопка «Очистить историю» должна очищать таблицу, точки и сохранённые записи; после перезагрузки история должна оставаться пустой.

История хранится в `localStorage` браузера отдельно для каждого адреса сайта. При переходе с `localhost:8080` на другой адрес или порт прежняя история не переносится.
